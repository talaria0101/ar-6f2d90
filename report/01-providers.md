# Providers with a working public API: academic and archival services

Generated by `scripts/build_report.py` from `data/providers.tsv`. Every row names the captured response that proves it. Run `python3 scripts/check_reports.py` to re-verify all of them.

## What the columns mean

| column | meaning |
|---|---|
| `provider` | the organisation that operates the API. Several endpoints from one provider are listed separately. |
| `service` | the specific endpoint set. |
| `auth` | what the anonymous probe needed. `none` answered with no credential at all; `key-optional` answered anonymously and also documents a keyed mode with a higher allowance; `demo-key` answered only when the published demo key that appears in the vendor's own documentation was supplied; `email-required` wants a contact address in the query. Every `demo-key` row was also probed with no credential at all and refused, so the key is load-bearing, not decorative. `key-required` means the anonymous probe returned a refusal; no `key-required` row is in this table. |
| `observed` | one fact read out of the captured body: a result count, a row count, an identifier, or the document shape. |
| `bytes` / `sha256` | size and digest of the captured body. |
| `evidence_path` | the captured body itself. |

The `observed` figure is not a vendor claim. It is the number the service returned to a single unauthenticated request made from this sandbox on 2026-10-20, with the query shown in the probe URL. A different query returns a different number; the figure proves the endpoint answered, not that the corpus is that size.
